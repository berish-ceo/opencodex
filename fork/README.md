# Форк opencodex

Здесь живут наши правки к [opencodex](https://github.com/lidge-jun/opencodex). Ветка `berish` состоит из релиза
upstream и наших коммитов поверх него. Установленный пакет `@bitkyc08/opencodex` запускает исходники (`src/*.ts`
через bun), поэтому `src/` ветки накладывается прямо на файлы глобального npm-пакета той же версии.

## Что в форке

| Коммит | Что делает |
|---|---|
| `chore(fork)` | Эта папка: скрипт `ocx-fork.sh` и документация |
| `feat(anthropic)` | Управление кэшем промптов Anthropic: `cacheRetention: "hybrid"`, `subagentCacheRetention`, `cacheRetention` и `cacheKeepalive` у комбо, пометки в журнале запросов |
| `feat(responses)` | Короткие ссылки вместо больших конвертов reasoning `ocxr1` |

В режиме `hybrid` системный промпт, инструменты и два последних сообщения человека кэшируются на 1 час, а хвост
агентного цикла на 5 минут. `subagentCacheRetention` задаёт отдельный TTL субагентам, которых запускает codex-rs.
`cacheRetention` у комбо публикует одну модель под разными TTL, а `cacheKeepalive` раз в 270 секунд повторяет
последний запрос потока с `max_tokens: 0` и продлевает 5-минутный кэш без генерации ответа.

`~/.opencodex/config.json` использует эти ключи в комбо `opus-ttl5-p30`, `sonnet-ttl5-p30`, `haiku-ttl5-p30`
(5 минут и keepalive) и `opus-ttl60`, `sonnet-ttl60`, `haiku-ttl60` (1 час). Без форка эти ключи не действуют.

Уровень `ultra` у этих комбо держится на лестницах `providers.anthropic.modelReasoningEfforts` и флаге
`providers.anthropic.modelReasoningEffortsAuthoritative: true`. Без флага opencodex при каждой загрузке конфига
заменяет лестницы OAuth-провайдера лестницами пресета, и `ultra` пропадает.

Короткие ссылки убирают ранний автокомпакт Codex на моделях Claude. Codex прибавляет к реальному usage провайдера
оценку каждого прошлого reasoning-элемента по длине его `encrypted_content`, а подпись Claude thinking раздувает
такой элемент до 5–15 тыс. символов: в длинной сессии набегали сотни тысяч лишних токенов. Мост Responses отдаёт
клиенту вместо большого конверта короткую ссылку, а сам конверт хранит в `~/.opencodex/reasoning-envelopes.sqlite`.
Разбор запроса подставляет конверт обратно байт в байт, поэтому запрос к Anthropic и его кэш не меняются.

Codex может вернуться к любому чату, поэтому срока хранения у строк нет: при превышении 2 ГБ вытесняются давно
не использованные. Не удаляйте этот файл. Если строки нет (файл удалён, чат передан на другой хост или форк снят),
прокси пишет одно предупреждение в `~/.opencodex/service.log`, а Claude продолжает чат без скрытых рассуждений
тех шагов. После повторной установки ссылки снова работают, потому что `revert` файл не трогает.

## Ветки, теги и remote

| Что | Назначение |
|---|---|
| `berish` | Релиз upstream `vX.Y.Z` и наши коммиты; ветка по умолчанию в форке |
| `berish-vX.Y.Z`, `berish-vX.Y.Z-r2` | Проверенные состояния ветки; `install` ставит только их |
| `dev` | Копия ветки upstream, мы её не меняем |
| `origin` | Форк [berish-ceo/opencodex](https://github.com/berish-ceo/opencodex) |
| `upstream` | [lidge-jun/opencodex](https://github.com/lidge-jun/opencodex), только чтение: пуш отключён |
| `.git/ocx-fork/` | Локальное состояние скрипта: Bun для тестов и дифф, наложенный на пакет |

Ветка стоит на релизном теге, а не на `dev`: `src/` ветки ложится на npm-пакет той же версии, поэтому её база
обязана совпадать с выпущенным релизом. Скрипт сверяет коммит тега с `gitHead` пакета в npm.

Upstream сам в форк не попадает. GitHub не синхронизирует форк без кнопки Sync fork или `gh repo sync`, а ветку
`berish` двигает только `ocx-fork.sh prepare`. Не нажимайте Sync fork на ветке `berish`: GitHub предложит влить
в неё `dev` upstream, а это не релиз.

`git range-diff berish-v2.100.2 berish-v2.101.0` показывает, как изменились наши коммиты между версиями.

## Обновление opencodex

Не обновляйте opencodex кнопкой в GUI или голой командой `ocx update`: они ставят чистый пакет и снимают форк.
Обновляйте так:

```sh
~/Desktop/projects/opencodex/fork/ocx-fork.sh update
```

Скрипт:

1. узнаёт последнюю версию в npm, скачивает её тег из upstream и сверяет его с `gitHead` пакета;
2. переносит ветку `berish` на новый тег командой `git rebase --onto`;
3. запускает `bun install`, `tsc --noEmit`, тесты форка и проверки раскладки тестов и `structure/`; тесты идут
   на версии bun из `package.json#testRunnerBun`;
4. ставит на ветку тег `berish-v<версия>`;
5. заранее скачивает новый пакет в кэш npm, закрывает приложение OpenCodex, вызывает штатный `ocx update`,
   накладывает `src/` ветки на установленный пакет, перезапускает прокси через launchd-сервис, ждёт `ocx health`,
   проверяет, что порт держит npm-пакет, и снова открывает приложение.

Перед `ocx update` скрипт копирует `~/.opencodex/config.json` и `~/.codex/config.toml` в
`~/.opencodex/backups/pre-<версия>-<время>`. `ocx update` при остановке прокси убирает из `config.toml` модель по
умолчанию, если её обслуживает прокси, а при запуске возвращает только ключи маршрутизации; скрипт возвращает
сохранённую строку `model = ...`.

При конфликте или упавшей проверке скрипт останавливается до шага 5, и установленная версия остаётся рабочей.
Тогда попросите агента: «перенеси форк opencodex, см. ~/Desktop/projects/opencodex/fork/AGENTS.md».

После успешного обновления опубликуйте ветку и тег; скрипт печатает нужную команду:

```sh
git -C ~/Desktop/projects/opencodex push --force-with-lease origin berish berish-v<версия>
```

## Другие команды

| Команда | Действие |
|---|---|
| `status` | Установленная версия, стоит ли форк, база ветки и её тег, последняя версия в npm, кто держит порт, наши коммиты и следующий шаг, если пакет и ветка расходятся |
| `serve` | Вернуть прокси на npm-пакет с форком, если порт занял встроенный `ocx` приложения |
| `prepare [версия]` | Шаги 1–4 для указанной версии (по умолчанию последней) без установки |
| `finalize <версия>` | Проверить ветку после ручных правок или разрешения конфликтов и поставить тег |
| `install` | Наложить проверенную ветку на установленный пакет и перезапустить прокси |
| `revert` | Снять форк с установленного пакета и перезапустить прокси |

Если пакет уже обновили без скрипта, выполните `prepare <установленная версия>`, затем `install`.

## Приложение OpenCodex в меню

`/Applications/OpenCodex.app` не использует установленный CLI. Внутри приложения лежит своя скомпилированная копия
`ocx` (`Contents/MacOS/ocx`) той же версии, что и приложение, и форк на неё не ложится. Поэтому приложение и CLI
обновляются раздельно и их версии расходятся.

Обе программы запускают один и тот же прокси на порту 10100, и работает тот, кто занял порт первым. Если порт занят,
приложение подключается к работающему прокси и только показывает статистику. Если порт свободен, например пока
перезапускается CLI, приложение поднимает свою копию `ocx`, и форк перестаёт действовать. Строка `serving` в
`status` показывает, кто держит порт; при `OpenCodex.app bundled ocx` выполните `serve`.

Удобнее держать приложение не новее CLI: тогда оно молча подключается гостем. Если версия приложения та же или новее,
при ручном запуске оно предлагает забрать управление прокси (takeover) и не запоминает отказ. Отказывайтесь каждый
раз: согласие передаёт порт копии без форка и блокирует обновление CLI.

## Новые правки

1. Работайте в `~/Desktop/projects/opencodex` на ветке `berish`. Правка существующей функции идёт в её коммит:
   `git commit --fixup <коммит>`, затем `git rebase -i --autosquash v<база>`. Новая функция получает свой коммит.
2. Новый тестовый файл регистрируется в `scripts/test-layout/layout.json` и `tests/fixtures/test-layout-expected.json`.
3. `fork/ocx-fork.sh finalize <база>` проверяет ветку и ставит тег `berish-v<база>-r<n>`, затем
   `fork/ocx-fork.sh install`. `install` сам снимает прежнюю ревизию форка, если она стоит на пакете.
4. Опубликуйте ветку и тег командой из вывода `finalize`.

## Откат

`fork/ocx-fork.sh revert` возвращает стоковый пакет той же версии. Чтобы вернуть прежнюю ревизию форка на той же
версии, переставьте ветку на её тег (`git reset --hard berish-v<версия>` на ветке `berish`) и выполните `install`.
